7. Neo4j Student–Course Graph
Create Students and Courses
CREATE
(a:Student {name:'Abdul'}),
(b:Student {name:'Pooja'}),
(c:Student {name:'Rahul'}),
(d:Student {name:'Nidhi'}),
(e:Student {name:'Palak'}),

(x:Course {name:'BCA'}),
(y:Course {name:'BBA'}),
(z:Course {name:'MCA'});
Relationships
MATCH (s:Student {name:'Abdul'}),(c:Course {name:'BCA'})
CREATE (s)-[:ENROLLED_IN]->(c);

MATCH (s:Student {name:'Pooja'}),(c:Course {name:'BCA'})
CREATE (s)-[:ENROLLED_IN]->(c);

MATCH (s:Student {name:'Rahul'}),(c:Course {name:'BBA'})
CREATE (s)-[:ENROLLED_IN]->(c);

MATCH (s:Student {name:'Nidhi'}),(c:Course {name:'BCA'})
CREATE (s)-[:ENROLLED_IN]->(c);

MATCH (s:Student {name:'Palak'}),(c:Course {name:'BBA'})
CREATE (s)-[:ENROLLED_IN]->(c);
Queries
// All students
MATCH (s:Student) RETURN s;

// Students in BCA
MATCH (s:Student)-[:ENROLLED_IN]->(c:Course {name:'BCA'})
RETURN s;

// Courses of Abdul
MATCH (s:Student {name:'Abdul'})-[:ENROLLED_IN]->(c)
RETURN c;

// Add relationship
MATCH (s:Student {name:'Abdul'}),(c:Course {name:'MCA'})
CREATE (s)-[:ENROLLED_IN]->(c);

// Remove relationship
MATCH (s:Student {name:'Abdul'})-[r:ENROLLED_IN]->(c:Course {name:'MCA'})
DELETE r;

13. Sharding + Replication
                Application
                     |
              Sharded Database
             /        |        \
          Shard 1   Shard 2   Shard 3
           /   \      /   \      /   \
         P1    S1    P2    S2   P3    S3
Sharding: Data distributed between shards.
Replication: Each shard has replica nodes.
Scalability: More shards can be added.
Fault tolerance: Replica can serve when primary fails.

15. Database Distribution Models
Model	Data Distribution	Failure Handling	Advantage	Limitation	Application
Single Server	One server	Server failure affects service	Simple	Limited scalability	Small application
Sharding	Across servers	Other shards continue	High scalability	Complex setup	Big Data
Master-Slave	Primary + replicas	Secondary can take over	Data redundancy	Primary coordination	Banking
Peer-to-Peer	Across equal nodes	Other nodes available	No single master	Complex consistency	Cassandra
Sharding + Replication	Shards + replicas	Replica handles failure	Scalability + fault tolerance	Most complex	Large cloud systems
Simple Architectures
1. Single Server
Client → Server → Database
2. Sharding
             Database
          /     |     \
      Shard1  Shard2  Shard3
3. Master-Slave
             Primary
            /       \
       Secondary  Secondary
4. Peer-to-Peer
       Node1 ↔ Node2
         ↕       ↕
       Node3 ↔ Node4
5. Sharding + Replication
       Shard 1       Shard 2
       P ─ S         P ─ S
       P ─ S         P ─ S
